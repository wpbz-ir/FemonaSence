# هاست موردنیاز برای راه‌اندازی واقعی فمونا سنس

این پروژه یک سامانه پخش/دانلود ویدئو با ربات تلگرام است. مصرف منابع عمدتاً توسط
**ترافیک ویدئو (پهنای باند)**، **پردازش تبدیل کیفیت (FFmpeg)** و **حجم فایل‌ها (دیسک)** تعیین می‌شود — نه کد.

## ۱) نوع هاست: VPS (سرور مجازی) — نه هاست اشتراکی

هاست اشتراکی (مثل هاست‌های cPanel داخل ایران) به هیچ عنوان مناسب نیست؛ دلیل:
- اجرای پروسه‌های دائمی (ربات polling، ورکر تبدیل ویدئو، ورکر runtime) ممنوع است.
- PostgreSQL و Redis و FFmpeg نصب نمی‌شوند.
- پورت‌های خروجی به api.telegram.org معمولاً محدود است.

**گزینه پیشنهادی (به ترتیب):**
1. **VPS خارج ایران** (آلمان/فنلاند/هلند) — دسترسی بدون فیلترینگ به api.telegram.org، پهنای باند بالا. تأخیر برای کاربر ایرانی ~۸۰–۱۵۰ms که برای پخش آنلاین با CDN داخلی‌سازی پوسترها قابل قبول است. پیشنهاد: Hetzner، Netcup، Contabo.
2. **VPS داخل ایران** — تأخیر عالی برای کاربر؛ اما خروجی به api.telegram.org ممکن است محدود شود (نیاز به پراکسی خروجی روی خود سرور). فقط اگر اپراتور سرور راه‌حل خروجی دارد.
3. ترکیبی: ربات+پنل روی هاست خارج، یا CDN جلوی فایل‌های پخش.

## ۲) مشخصات سخت‌افزاری

### سطح شروع (تا ~۵۰۰ کاربر فعال، تا ~۱۰ پخش هم‌زمان)
| منبع | مقدار | توضیح |
|---|---|---|
| CPU | ۴ هسته vCPU | ۲ هسته برای FFmpeg هنگام ساخت نسخه‌های ۴۸۰/۷۲۰/۱۰۸۰ + ۲ هسته برای API/ربات/PostgreSQL |
| RAM | ۸ GB | FFmpeg هنگام ترنسکد ۱۰۸۰p تا ~۲GB؛ بقیه برای PostgreSQL(۱GB)، Redis(۲۵۶MB)، uvicorn، ربات |
| دیسک | ۱۰۰–۲۰۰ GB NVMe | فایل‌های موقت ترنسکد (هر وظیفه تا ۲–۳ برابر حجم فیلم) + سیستم. فایل‌های اصلی در Storage تلگرام نگهداری می‌شوند و دیسک دائمی نمی‌گیرند |
| پهنای باند | **حداقل ۵–۱۰ TB/ماه، پورت ≥۱Gbps** | پخش آنلاین یک فیلم ۱۰۸۰p ≈ ۱–۲.۵GB به‌ازای هر تماشای کامل. مهم‌ترین محدودیت واقعی شما همین است |
| سیستم‌عامل | Ubuntu 24.04 LTS | (پروژه روی ویندوز هم اجرا می‌شود ولی لینوکس پایدارتر و ارزان‌تر است) |

### سطح رشد (~۱۰۰۰–۵۰۰۰ کاربر، ۲۰–۵۰ پخش هم‌زمان)
| منبع | مقدار |
|---|---|
| CPU | ۸ vCPU |
| RAM | ۱۶ GB |
| دیسک | ۴۰۰ GB NVMe |
| پهنای باند | ۲۰–۳۰ TB/ماه یا unmetered |

> 💡 اگر تبدیل کیفیت را کمتر انجام دهید (فقط نسخه اصلی را آپلود کنید)، CPU ۲ هسته هم برای شروع کافی است؛ FFmpeg سنگین‌ترین مصرف‌کننده CPU است.

## ۳) الزامات نرم‌افزاری روی سرور

- **Python 3.13+** (پروژه با ۳.۱۴ تست شده)
- **PostgreSQL ۱۷** + **Redis ۸** (در مخزن `compose.yaml` آماده است: `docker compose up -d postgres redis`)
- **FFmpeg + FFprobe** (برای پردازش کیفیت — `FFMPEG_BIN`/`FFPROBE_BIN`)
- **Caddy** (قالب `deploy/Caddyfile.template` در مخزن هست): HTTPS خودکار با Let's Encrypt + پروکسی به `127.0.0.1:8000`
- **دامنه + SSL**: برای webhook تلگرام و پخش آنلاین، https اجباری است (`PUBLIC_BASE_URL=https://…`)
- اختیاری: **Docker** فقط برای Postgres/Redis؛ خود اپ نکسته اجرا می‌شود.

## ۴) نکات تلگرامی مهم (روی هاست)

1. **محدودیت ۲۰ مگابایت Bot API**: دانلود فایل با `getFile` برای ربات معمولی حداکثر ۲۰MB است. دو راه‌حل:
   - اجرای **Bot API Server محلی** (telegram-bot-api) کنار پروژه: سقف به ۲GB می‌رسد و متغیرهای `TELEGRAM_BOT_API_BASE_URL` + `TELEGRAM_LOCAL_FILE_ROOT` در `.env` تنظیم می‌شود. پخش آنلاین فایل‌های بزرگ از همین مسیر امکان‌پذیر می‌شود.
   - یا درج مستقیم لینک پخش (مثلاً از یک فایل‌سرور https) در کپشن پیام کانال ذخیره‌سازی با فرمت `STREAM_URL: https://…` — کانال‌پست این لینک را خودکار در `StorageFile` ثبت می‌کند.
2. **ربات باید ادمین کانال Storage و کانال‌های عضویت اجباری باشد** تا `getChatMember` جواب دهد.
3. **webhook**: بعد از تنظیم دامنه، `python scripts/set_webhook.py` را اجرا کنید و `TELEGRAM_MODE=webhook` بگذارید.

## ۵) چک‌لیست استقرار روی هاست

```bash
# ۱. زیرساخت
apt update && apt install -y python3.13 python3.13-venv postgresql redis-server ffmpeg caddy
# (یا docker compose up -d برای postgres+redis)

# ۲. کد و محیط مجازی
git clone <repo> /opt/femona && cd /opt/femona
python3.13 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# ۳. پیکربندی
cp .env.example .env   # مقادیر production طبق docs/SYSTEM_STATUS_GUIDE_FA.md
python -m alembic upgrade head
python scripts/seed_initial_data.py   # فقط بار اول (ادمین ارشد و پلن‌ها)

# ۴. اجرا (سه پروسه جدا + ربات)
uvicorn app.api.main:app --host 127.0.0.1 --port 8000
python -m app.workers.media_worker
python -m app.workers.runtime_worker
python main.py            # در حالت polling؛ در webhook اجرا نکنید

# ۵. سلامت
curl http://127.0.0.1:8000/health/ready
```

هر ۴ پروسه را با systemd unit جدا (یا `register_tasks.ps1` روی ویندوز) بالا نگه دارید و لاگ‌ها را به فایل هدایت کنید.
