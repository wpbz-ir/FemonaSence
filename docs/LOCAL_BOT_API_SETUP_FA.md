# راهنمای فعال‌سازی سرور Bot API محلی تلگرام (برای پردازش فایل‌های حجیم)

## چرا لازم است؟

تلگرام روی **Bot API ابری رسمی** سقف‌های سختی دارد:

| عملیات | Bot API ابری | Bot API محلی (`--local`) |
|---|---|---|
| دانلود فایل (`getFile`) | حداکثر **۲۰ مگابایت** | حداکثر **۲ گیگابایت** |
| ارسال ویدیو (`sendVideo`) | حداکثر **۵۰ مگابایت** | حداکثر **۲ گیگابایت** |

به همین دلیل هر «پردازش کیفیت» روی فیلم‌های معمولی (چند صد مگابایت به بالا) بدون
سرور محلی، در مرحلهٔ دانلود شکست می‌خورد. با فعال‌سازی سرور محلی، خط تولید کیفیت
(۴۸۰p/۷۲۰p/۱۰۸۰p) روی فایل‌های حجیم کار می‌کند.

## پیش‌نیازها

- Docker Desktop برای ویندوز (از docker.com نصب کنید)
- `api_id` و `api_hash` از سایت https://my.telegram.org
  (بخش **API development tools** — یک‌بار برای همیشه می‌گیرید)

## گام ۱ — اجرای سرور محلی با Docker

در PowerShell:

```powershell
docker run -d --name telegram-bot-api `
  -v telegram-bot-api-data:/var/lib/telegram-bot-api `
  -p 8081:8081 `
  --restart unless-stopped `
  aiogram/telegram-bot-api:latest `
  --local --http-port 8081 `
  --api-id=شناسه_API_شما `
  --api-hash=کد_API_شما
```

بررسی سلامت (به‌جای TOKEN توکن ربات خودتان):

```powershell
curl.exe http://127.0.0.1:8081/botTOKEN/getMe
```

اگر پاسخ JSON با `"ok":true` برگشت، سرور محلی آماده است.

## گام ۲ — تنظیم فایل `.env`

در فایل `C:\CinemaVault\.env` این خط را اضافه/ویرایش کنید:

```
TELEGRAM_BOT_API_BASE_URL=http://127.0.0.1:8081
```

نکته: مقدار `TELEGRAM_LOCAL_FILE_ROOT` لازم نیست تغییر کند؛ اگر پاسخ `getFile`
مسیر داخل کانتینر داد، برنامه به‌صورت خودکار از همان سرور محلی دانلود HTTP
انجام می‌دهد (مسیر ناامن یا خارج از محدوده هم به‌صورت ایمن رد می‌شود).

## گام ۳ — راه‌اندازی مجدد

```powershell
cd C:\CinemaVault
.\deploy\stop_production.ps1
.\deploy\production.ps1
```

## گام ۴ — تست پردازش کیفیت

1. پنل مدیریت (`http://127.0.0.1:8000/admin`) → «پردازش کیفیت»
2. عنوان و نسخهٔ مبنا را انتخاب کنید و «ساخت پردازش» بزنید.
3. در «وظایف رسانه» پیشرفت jobها را ببینید؛ خطاها (در صورت وجود) حالا به فارسی
   و در جدول «پردازش‌های اخیر» زیر هر کیفیت نمایش داده می‌شوند.

## عیب‌یابی

- **کانتینر بالا نمی‌آید؟** لاگ را ببینید: `docker logs telegram-bot-api`
- **`api_id/api_hash` نامعتبر است؟** دوباره از my.telegram.org بگیرید؛ نباید
  حساب تلگرام محدود شده باشد.
- **دانلود کند است؟** سرور محلی فایل را از دیتاسنتر تلگرام می‌گیرد؛ اگر سرعت
  پایین است، مسیر شبکه سرور را بررسی کنید (برای سرعت واقعی، اجرای کل سرویس
  روی سرور مجازی خارج از کشور توصیه می‌شود — `docs/HOSTING_REQUIREMENTS_FA.md`).
- برای توقف/حذف کانتینر: `docker stop telegram-bot-api` و
  `docker rm telegram-bot-api` (داده‌ها در volume باقی می‌ماند).

## نکته‌های امنیتی

- پورت 8081 فقط روی `127.0.0.1` در دسترس است (Docker به‌صورت پیش‌فرض روی همهٔ
  اینترفیس‌ها bind می‌کند؛ اگر نگرانید در فایروال ویندوز پورت 8081 ورودی را ببندید).
- هرگز `api_hash` را در ریپازیتوری یا چت به اشتراک نگذارید.
